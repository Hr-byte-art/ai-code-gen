# 项目优化建议

## 代码质量

### 1. 清除死代码
- **文件**：`AiCodeGeneratorFacade.java:225-460`
- **问题**：约 240 行注释掉的旧方法，应直接删除，用 git history 替代版本管理
- **影响**：代码可读性差，维护成本高

### 2. 消除重复工作流
- **文件**：`CodeGenWorkflow.java`、`CodeGenConcurrentWorkflow.java`
- **问题**：共享大量相同的节点定义和路由逻辑（`routeAfterQualityCheck`、`routeBuildOrSkip`）
- **优化**：抽取公共基类或模板方法

### 3. AI Model 配置类过多
- **文件**：`config/ai/` 下 6 个独立 Config 类
- **问题**：Default/Detection/GenAppName/Reasoning/Streaming/Routing 结构高度相似
- **优化**：抽取参数化的工厂配置减少样板代码

### 4. 敏感词硬编码
- **文件**：`PromptSafetyInputGuardrail.java`
- **问题**：敏感词列表和注入模式直接写死在代码中
- **优化**：外置到配置文件或数据库，便于运营人员动态维护

### 5. Content-Type 硬编码
- **文件**：`StaticResourceController.java:75-82`
- **问题**：手动映射 MIME 类型，遗漏了 `.svg`、`.json`、`.woff2` 等常见类型
- **优化**：使用 `MediaTypeFactory` 或 `Files.probeContentType()`

---

## 性能优化

### 6. 忙等待问题
- **文件**：`VueProjectBuilder.java:52-75`
- **问题**：使用 `Thread.sleep(1000)` 轮询文件是否存在
- **优化**：改用 `WatchService` 或 `CountDownLatch`

### 7. 缺少结构化监控指标
- **问题**：虽然有 `MonitorContext` + Prometheus 端点，但日志主要靠 `log.info/warn`
- **优化**：接入 Micrometer 自定义 Counter/Timer，记录生成耗时、token 用量、错误率

### 8. `e.printStackTrace()` 残留
- **文件**：`AiCodeGeneratorFacade.java:213`
- **问题**：直接调用 `e.printStackTrace()` 输出到 stderr
- **优化**：替换为 `log.error` 并带上完整堆栈

---

## 测试覆盖

### 9. 测试覆盖不足
- **现状**：仅 14 个测试文件
- **缺失**：Controller 层集成测试、Service 层单元测试、异常路径测试
- **优先级**：优先补 `AppController` 和 `AiCodeGeneratorFacade` 的测试
